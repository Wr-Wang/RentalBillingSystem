## 三、账期（Period）vs 账单月（BillMonth）分析与回退

### 3.1 发现问题

BillMonth 计算逻辑（SQL 25日截点规则）：
```
25日20:00前出账 → BillMonth = BilledAt月 + 1
25日20:00后出账 → BillMonth = BilledAt月 + 2
```

BillJob 固定 25 日 22:00 执行 → BillMonth 永远 = Period + 2 个月

### 3.2 用户选择与回退

| 阶段 | 操作 | 结果 |
|------|------|------|
| 用户选"DB 层偏移" | Period = targetMonth+1, BillMonth = Period | Period 和 BillMonth 强行一致 |
| 用户说"账期和账单月不是同一概念" | **完整回退** | 重加 BillMonth 列，恢复原始 CASE 计算，Period 回退 targetMonth |

### 3.3 最终状态

- Period = targetMonth（会计归属期，独立）
- BillMonth = 按 BilledAt 25日截点计算（独立）
- UI 同时显示"账期"和"账单月"两列，表头带 `InfoFilled` 图标提示说明

## 四、系统架构分析记录

### 4.1 API 调用日志原理

```
中间件(Middleware) → Channel(缓冲区) → 后台服务(BackgroundService) → 数据库
```

- ApiLoggingMiddleware：拦截 HTTP 请求/响应，读取 Body，Stopwatch 计时
- ApiLogChannel：Singleton，容量 2000，满时丢弃最旧
- ApiLogWriterService：2 秒/50 条批量 INSERT

### 4.2 中间件原理

- 管道模型（俄罗斯套娃）：注册顺序决定执行顺序
- `await _next(context)` 前后分别为请求阶段和响应阶段
- 中间件用于 HTTP 管道层，AOP 用于方法调用层

### 4.3 依赖注入

- 4 种注入方式：构造函数注入（主力）、属性注入（未用）、方法注入（少量）、服务定位器（特殊场景）
- 服务注册 = 告诉 DI 容器"这个接口用这个类来实现"

## 五、并发处理能力分析

### 5.1 并发架构

```
① 公司间并行（Parallel.ForEachAsync, CPU/2）
② 公司内串行（foreach, 上游失败阻断下游）
③ 合同级并行（BillJob/SettleJob, MaxDegree=20）
④ 单合同串行（foreach）
```

### 5.2 已修复的并发问题

| 问题 | 严重度 | 修复 |
|------|--------|------|
| `static SemaphoreSlim(2,2)` 全局锁 | 🔴 高 | 删除静态信号量，由调度引擎管理并发 |
| `CommitWithRetryAsync` 捕获所有异常重试 | 🟡 中 | 改为仅重试可恢复异常（死锁1205/超时-2/快照3960） |
| RowVersion 乐观锁未实装 | 🔴 高 | DapperUnitOfWork UPDATE 加入 `WHERE RowVersion=@RowVersion` |
| `GetAwaiter().GetResult()` 6 处同步阻塞 | 🟡 中 | 全部改为 async/await |

### 5.3 未修复的并发问题

| 问题 | 原因 |
|------|------|
| 并行度硬编码（20/16）不可配置 | 需增加配置系统支持 |
| 无死锁检测/超时机制 | 调度引擎上游卡住可阻塞下游 |
| 连接池 100 偏紧 | 20+20+16+HTTP = 潜在瓶颈 |
