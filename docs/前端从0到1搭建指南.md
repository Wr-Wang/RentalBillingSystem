# 第 0 章 环境与脚手架

## 0.1 前置条件

- Node.js 20+（`node -v` 验证）
- 本地已有**可运行的后端**（提供 `/api/auth/login`、`/api/users`、`/api/roles`、`/api/menus` 等接口）
- 记下后端监听端口（本指南示例为 `5178`，如不同请改 `vite.config.js` 代理）

## 0.2 创建项目 + 安装依赖（逐条命令）

```bash
# 1. 用 Vite 官方脚手架创建 Vue3 + JS 项目（会生成 web/ 目录）
npm create vite@latest web -- --template vue

# 2. 进入目录
cd web

# 3. 安装脚手架自带基础依赖（vue / vite / @vitejs/plugin-vue）
npm install

# 4. 安装本框架第一版需要的运行时依赖
npm install vue-router@4 pinia element-plus @element-plus/icons-vue axios
```

**依赖用途：**

| 依赖 | 用途 |
|---|---|
| `vue-router@4` | 前端路由（登录页 / 主框架 / 子页面） |
| `pinia` | 状态管理（user / menu / app / notification 各 store） |
| `element-plus` | UI 组件库 |
| `@element-plus/icons-vue` | 菜单 / 按钮图标 |
| `axios` | HTTP 客户端（请求 / 响应拦截器） |

> 后续需要图表、Excel 导出时再装：`echarts vue-echarts exceljs xlsx jszip`，第一版不装。

### 第 3 步 新建 `web/src/utils/requestContext.js`

① state 变量 → ② `setEffectiveCompanyId` → ③ `getEffectiveCompanyId` → ④ `clearEffectiveCompanyId` → 导出。

```js
export function getEffectiveCompanyId() { return effectiveCompanyId }
export function clearEffectiveCompanyId() { effectiveCompanyId = null }
```

### 第 4 步 新建 `web/src/utils/broadcast.js`

① 频道常量 → ② `getChannel` 懒初始化 → ③ `broadcast` → ④ `onMessage` → ⑤ `closeChannel`。

跨标签页通信：一个标签页登出/提交审批，其他标签页即时同步，不用等轮询。

```js
// BroadcastChannel 跨标签页通信（登出/通知刷新即时同步）
const CHANNEL_NAME = 'rbs-broadcast'
let channel = null

function getChannel() {
  if (!channel) {
    try { channel = new BroadcastChannel(CHANNEL_NAME) } catch { return null }
  }
  return channel
}

export function broadcast(type, payload) {
  const ch = getChannel()
  if (!ch) return
  ch.postMessage({ type, payload, from: window.name || 'unknown' })
}

export function onMessage(type, handler) {
  const ch = getChannel()
  if (!ch) return () => {}
  function listener(event) {
    if (event.data?.type === type) handler(event.data.payload, event.data.from)
  }
  ch.addEventListener('message', listener)
  return () => { try { ch.removeEventListener('message', listener) } catch { /* 静默 */ } }
}

export function closeChannel() {
  if (channel) { channel.close(); channel = null }
}
```

### 第 5 步 新建 `web/src/api/request.js`

① import → ② 创建 axios 实例(`baseURL:'/api'`) → ③ 导出 `handleApiError` → ④ 请求拦截器(注入 token/companyId) → ⑤ 响应拦截器(剥壳 + 401/403/404/500/网络错误) → 导出实例。

**全局职责**：所有接口统一走这个实例——自动带 token、自动剥壳 `response.data`、401 自动登出跳登录页、500 统一提示。

```js
// Axios 客户端 — 注入 token/companyId、响应剥壳、统一错误处理
import axios from 'axios'
import { ElMessage } from 'element-plus'
import router from '../router'
import { getEffectiveCompanyId, clearEffectiveCompanyId } from '../utils/requestContext'
import { broadcast } from '../utils/broadcast'

const request = axios.create({ baseURL: '/api', timeout: 30000 })

export function handleApiError(e, defaultMsg = '操作失败') {
  ElMessage.closeAll()
  const status = e?.response?.status
  const data = e?.response?.data
  if (data?.code) {
    ElMessage.error(data.message || defaultMsg)
  } else if (status === 500) {
    ElMessage.error('系统错误，请稍后重试')
  } else {
    ElMessage.error(data?.message || data?.error || defaultMsg)
  }
}

// 请求拦截器：注入 JWT + 公司视角
request.interceptors.request.use(config => {
  const token = localStorage.getItem('token')
  if (token) config.headers.Authorization = `Bearer ${token}`
  const companyId = getEffectiveCompanyId()
  if (companyId) {
    config.params = config.params || {}
    config.params.companyId = companyId
  }
  return config
}, error => Promise.reject(error))

// 响应拦截器：剥壳 response.data + 全局 HTTP 错误处理
request.interceptors.response.use(
  response => {
    if (response.config.method !== 'get') broadcast('NOTIFICATION_REFRESH')
    return response.data
  },
  error => {
    if (error.response) {
      switch (error.response.status) {
        case 401:
          localStorage.removeItem('token')
          localStorage.removeItem('userId')
          localStorage.removeItem('currentCompanyId')
          clearEffectiveCompanyId()
          broadcast('LOGOUT')
          router.push('/login')
          ElMessage.closeAll()
          ElMessage.error('登录已过期，请重新登录')
          break
        case 403:
          ElMessage.error(error.response.data?.message || '没有权限执行此操作，请联系管理员')
          break
        case 404:
          ElMessage.error('请求的资源不存在')
          break
        case 500:
          ElMessage.error('服务器错误')
          break
        default:
          ElMessage.error(error.response.data?.message || '请求失败')
      }
    } else {
      ElMessage.error('网络连接失败')
    }
    return Promise.reject(error)
  }
)

export default request
```

### 第 7 步 新建 `web/src/store/user.js`

① state(token/userId/user/permissions/company 相关) → ② `setUserData`(内部同步 requestContext) → ③ `login` → ④ `loadUserProfile` → ⑤ `logout` → ⑥ `hasPermission` → ⑦ return 导出。

**安全设计**：localStorage 只存 `token` + `userId`（用于刷新恢复登录态）；`user` / `permissions` 等敏感信息只存 Pinia 内存，页面刷新后通过 `loadUserProfile()` 从后端重新拉取——防止 XSS 篡改本地权限。

```js
// 用户状态 — token/userId 存 localStorage，user/permissions 仅存内存
import { defineStore } from 'pinia'
import { ref } from 'vue'
import { login as loginApi, getMyProfile } from '../api/index'
import { setEffectiveCompanyId, clearEffectiveCompanyId } from '../utils/requestContext'

export const useUserStore = defineStore('user', () => {
  const token = ref(localStorage.getItem('token') || '')
  const userId = ref(localStorage.getItem('userId') || '')
  const user = ref({})
  const permissions = ref([])
  const companyId = ref(null)          // 用户所属公司
  const isSuperAdmin = ref(false)
  const currentCompanyId = ref(null)   // 超管当前切换视角
  const companyList = ref([])
  const profileLoaded = ref(false)

  function setUserData(payload, tokenVal) {
    const userData = payload.user || payload
    token.value = tokenVal || token.value
    user.value = { ...userData, roles: userData.roles || payload.roles || [] }
    permissions.value = payload.permissions || []
    companyId.value = userData.companyId || null
    isSuperAdmin.value = userData.isSuperAdmin || false
    companyList.value = userData.companyList || []
    currentCompanyId.value = userData.defaultCompanyId || null
    setEffectiveCompanyId(isSuperAdmin.value ? currentCompanyId.value : companyId.value)
    profileLoaded.value = true
  }

  async function login(credentials) {
    const res = await loginApi(credentials)
    const tokenVal = res.token || res.accessToken
    setUserData(res, tokenVal)
    localStorage.setItem('token', tokenVal)
    localStorage.setItem('userId', (res.user?.id || '').toString())
    return res
  }

  async function loadUserProfile() {
    if (!token.value || profileLoaded.value) return
    try {
      const res = await getMyProfile()
      setUserData(res, token.value)
    } catch (e) {
      logout()
      throw e
    }
  }

  function logout() {
    token.value = ''; userId.value = ''
    user.value = {}; permissions.value = []
    companyId.value = null; isSuperAdmin.value = false
    currentCompanyId.value = null; companyList.value = []
    profileLoaded.value = false
    localStorage.removeItem('token')
    localStorage.removeItem('userId')
    localStorage.removeItem('currentCompanyId')
    clearEffectiveCompanyId()
  }

  function hasPermission(code) {
    return permissions.value.includes(code)
  }

  return {
    token, userId, user, permissions, companyId, isSuperAdmin,
    currentCompanyId, companyList, profileLoaded,
    login, logout, hasPermission, loadUserProfile
  }
})
```

### 第 9 步 新建 `web/src/store/menu.js`

① state(`sidebarMenus`/`permCodeMap`) → ② `fetchPermCodeMap` → ③ `initFromRoutes` → ④ `buildMenusFromRoutes`/`isMenuVisible` → ⑤ return。

**核心机制**：侧边栏菜单**不是单独配出来的**，而是由 router 的路由表 + 每条的 `meta` 自动构建。这样你第 4 章加菜单时，只需改 router 一处。

```js
// 菜单状态 — 由路由 meta 构建侧边栏菜单 + 权限码过滤
import { defineStore } from 'pinia'
import { ref, watch } from 'vue'
import { useUserStore } from './user'
import { getMenus } from '../api/index'

export const useMenuStore = defineStore('menu', () => {
  const sidebarMenus = ref([])
  let cachedRoutes = []
  let permCodeMap = {}

  function normalizePath(p) {
    let s = p.startsWith('/') ? p : '/' + p
    if (s.length > 1 && s.endsWith('/')) s = s.slice(0, -1)
    return s
  }

  async function fetchPermCodeMap() {
    try {
      const menuTree = await getMenus()
      const map = {}
      const walk = menus => {
        for (const m of menus) {
          if (m.path && m.permissionCode) map[normalizePath(m.path)] = m.permissionCode
          if (m.children?.length) walk(m.children)
        }
      }
      walk(Array.isArray(menuTree) ? menuTree : [])
      permCodeMap = map
    } catch { permCodeMap = {} }
  }

  async function initFromRoutes(routes) {
    cachedRoutes = routes || []
    await fetchPermCodeMap()
    rebuildMenus()
    const userStore = useUserStore()
    const unwatch = watch(() => userStore.profileLoaded, (loaded) => {
      if (loaded) { rebuildMenus(); unwatch() }
    }, { immediate: true })
  }

  function isMenuVisible(meta, fullPath, userStore, userRoles) {
    if (userStore.isSuperAdmin) return true
    if (meta.scope === 'System') return false
    if (meta.hidden) return false
    const permCode = permCodeMap[fullPath]
    if (permCode !== undefined) return userStore.hasPermission(permCode)
    if (meta.roles && meta.roles.length > 0) return meta.roles.some(r => userRoles.includes(r))
    return true
  }

  function rebuildMenus() {
    if (!cachedRoutes?.length) return
    const userStore = useUserStore()
    const userRoles = (userStore.user?.roles || []).map(r => r.code).filter(Boolean)
    const result = []
    for (const route of cachedRoutes) {
      if (route.hidden) continue
      const meta = route.meta || {}
      if (meta.scope === 'System' && !userStore.isSuperAdmin) continue
      const fullPath = normalizePath(route.path || '')
      const visibleChildren = (route.children || [])
        .filter(c => !(c.meta && c.meta.hidden))
        .filter(c => !(c.meta?.scope === 'System' && !userStore.isSuperAdmin))
        .filter(c => c.meta?.title)
        .filter(c => isMenuVisible(c.meta || {}, normalizePath(route.path + '/' + c.path), userStore, userRoles))
        .map(c => ({ id: c.path || c.name, parentId: fullPath, name: c.meta.title, path: c.path, fullPath: normalizePath(route.path + '/' + c.path), icon: c.meta.icon || '', sortOrder: c.meta.sortOrder || 0 }))
      const parentVisible = isMenuVisible(meta, fullPath, userStore, userRoles)
      if (!parentVisible && visibleChildren.length === 0) continue
      if (!meta.title && visibleChildren.length === 0) continue
      result.push({ id: route.path || route.name, parentId: null, name: meta.title || route.name || '', path: route.path || '', fullPath, icon: meta.icon || '', sortOrder: meta.sortOrder || 0, children: visibleChildren })
    }
    sidebarMenus.value = result
  }

  return { sidebarMenus, initFromRoutes, rebuildMenus }
})
```

### 第 10 步 新建 `web/src/store/notification.js`

① state(`notifications`/`unreadCounts`) → ② `fetchUnreadCounts` → ③ 轮询(`startPolling`/`stopPolling`) → ④ return。第一版给简化版（只计数），通知页后续版本再加。

```js
// 通知状态 — 未读计数 + 轮询（第一版简化：只计数，通知页后续版本再加）
import { defineStore } from 'pinia'
import { ref, reactive } from 'vue'
import { getUnreadCounts } from '../api'

export const useNotificationStore = defineStore('notification', () => {
  const unreadCounts = reactive({ Approval: 0, Renewal: 0, Collection: 0, System: 0, Total: 0 })
  let pollTimer = null
  let isPolling = false
  let pollInterval = 300000

  async function fetchUnreadCounts() {
    try {
      const res = await getUnreadCounts()
      unreadCounts.Approval = res.approval || 0
      unreadCounts.Renewal = res.renewal || 0
      unreadCounts.Collection = res.collection || 0
      unreadCounts.System = res.system || 0
      unreadCounts.Total = res.total || 0
    } catch { /* 静默 */ }
    finally { if (isPolling) scheduleNextPoll() }
  }

  function scheduleNextPoll(delay) {
    if (pollTimer) clearTimeout(pollTimer)
    pollTimer = setTimeout(fetchUnreadCounts, delay || pollInterval)
  }

  function startPolling(interval) {
    pollInterval = interval || pollInterval
    stopPolling()
    isPolling = true
    fetchUnreadCounts()
  }

  function stopPolling() {
    isPolling = false
    if (pollTimer) { clearTimeout(pollTimer); pollTimer = null }
  }

  return { unreadCounts, fetchUnreadCounts, startPolling, stopPolling }
})
```

## 1.3 公共类服务创建顺序

**（复用层，自底向上）**

```
utils（无依赖）
  → api/request（唯一依赖工具 + router）
  → api/index（接口清单）
  → store（依赖 api）
  → directive（依赖 store）
  → layout（依赖 store）
  → views（依赖 store / api）
  → router（依赖 views）
  → main.js（串联一切）
```

**原因**：每一层只依赖下面已建好的层，写完后立即可 import 验证，不会出现"后面还没建、前面已引用"的报错。

## 1.4 关键依赖解释

- **先 utils → 再 request → 再 api → 再 store → 再 layout/view → 再 router → 最后 main.js**：main.js 是唯一把所有东西串联起来的地方，它最依赖别人，所以最后写。
- **`requestContext` 必须最先建**：它避免了 `store ↔ request` 循环依赖（store 写 companyId，request 读 companyId，各不 import 对方）。
- **`request.js` 与 `router/index.js` 存在循环引用**（request 导入 router 用于 401 跳登录；router 的页面又依赖 api/request）。它能正常工作是因为 request.js 只在**拦截器回调里**使用 router，回调执行时 router 早已初始化完成。这是本项目刻意保留的既有写法，勿拆。
- **`menu.js` 为什么从路由构建**：让"加菜单"简化为"加一行路由"，菜单和页面永远同源，不会出现"有页面没菜单 / 有菜单没页面"。

# 第 2 章 登录功能（第一个功能）

> 框架地基已经包含了登录需要的全部代码（api 的 `login`、store 的 `login`/`loadUserProfile`、登录页、路由守卫、MainLayout 的 onMounted 链路）。本章解释这条链是如何走通的，并给出验证步骤。

## 2.1 后端接口契约

**`POST /api/auth/login`**

```jsonc
// 请求
{ "username": "admin", "password": "admin123" }

// 响应（登录成功后前端需要的字段）
{
  "token": "eyJhbGciOiJIUzI1NiIs...",
  "user": {
    "id": "xxx",
    "username": "admin",
    "displayName": "系统管理员",
    "companyId": null,
    "isSuperAdmin": true,
    "companyList": [],            // 超管可选公司列表
    "defaultCompanyId": null,     // 默认视角
    "roles": []                   // 角色数组
  },
  "permissions": ["system:users", "menu:config", "..."]  // 权限码数组
}
```

**`GET /api/auth/me`** — 页面刷新后拉取用户信息，返回结构与 login 响应里的 `user` + `permissions` 相同。

## 2.2 登录调用链（谁调用谁）

```
登录页 handleLogin
  → userStore.login({username, password})        // store/user.js 第 7 步
      → api.login(data)                          // api/index.js 第 6 步
          → request.post('/auth/login')          // api/request.js 第 5 步
              → 请求拦截器（暂无 token，跳过注入）
              → 后端验证用户名密码
              → 响应拦截器剥壳，返回业务 JSON
      → setUserData(res, token)                  // 写 Pinia 内存 + requestContext
      → localStorage 存 token + userId
  → 跳转 /dashboard

MainLayout onMounted（刷新场景）
  → userStore.loadUserProfile()                  // GET /auth/me
      → setUserData(res)                         // 恢复 user/permissions 到内存
  → menuStore.initFromRoutes()                   // 构建侧边栏菜单
```

**要点**：
- **localStorage 只存 token/userId**，刷新时凭 token 重新拉资料——不信任本地缓存的权限数据。
- **401 处理**：后端返回 401 → 响应拦截器清空登录态 + 广播 LOGOUT + 跳 /login。

## 2.3 验证登录

1. 启动后端（能访问 `/api/auth/login`）。
2. `npm run dev`，打开 http://localhost:5173 → 自动跳 /login。
3. 输入 `admin / admin123` 登录 → 跳 /dashboard，顶栏显示用户名，左侧出现"仪表盘"和"系统设置"菜单。
4. **F5 刷新** → 仍在登录态（token 还在，`loadUserProfile` 重新拉资料）。
5. 输入错误密码 → 提示"登录失败"。

**页面骨架**（每个 CRUD 页都长这样，背下来能套所有页面）：

```vue
      <el-button type="primary" @click="openCreate">

        <el-form-item label="用户名" prop="username">
          <el-input v-model="form.username" :disabled="isEdit" />
        </el-form-item>
        <el-form-item label="密码" prop="password" v-if="!isEdit">
          <el-input v-model="form.password" type="password" show-password placeholder="留空默认为 123456" />
        </el-form-item>
        <el-form-item label="姓名"><el-input v-model="form.displayName" /></el-form-item>
        <el-form-item label="手机号"><el-input v-model="form.phone" /></el-form-item>
        <el-form-item label="邮箱"><el-input v-model="form.email" /></el-form-item>

<script setup>
import { ref, onMounted } from 'vue'
import { ElMessage, ElMessageBox } from 'element-plus'
import { getUsers, createUser, updateUser, getRoles } from '../../../api/index'

const loading = ref(false)
const showDialog = ref(false)
const isEdit = ref(false)
const saving = ref(false)
const formRef = ref(null)
const list = ref([])
const roleList = ref([])

const form = ref({
  id: null, username: '', password: '', displayName: '', phone: '', email: '', roleIds: []
})
const rules = {
  username: [{ required: true, message: '请输入用户名', trigger: 'blur' }]
}

const showPwdDialog = ref(false)
const savingPwd = ref(false)
const pwdFormRef = ref(null)
const pwdForm = ref({ id: null, password: '', confirmPassword: '' })
const pwdRules = {
  password: [{ required: true, message: '请输入新密码', trigger: 'blur' }],
  confirmPassword: [
    { required: true, message: '请确认新密码', trigger: 'blur' },
    { validator: (rule, value, callback) => {
      if (value !== pwdForm.value.password) callback(new Error('两次密码不一致'))
      else callback()
    }, trigger: 'blur' }
  ]
}

async function fetchUsers() {
  loading.value = true
  try {
    const res = await getUsers()
    list.value = Array.isArray(res) ? res : []
  } catch (e) {
    list.value = []
  }
  loading.value = false
}

async function fetchRoles() {
  try {
    const res = await getRoles()
    roleList.value = Array.isArray(res) ? res : []
  } catch (e) {
    roleList.value = []
  }
}

function openCreate() {
  isEdit.value = false
  form.value = { id: null, username: '', password: '', displayName: '', phone: '', email: '', roleIds: [] }
  showDialog.value = true
}

function openEdit(row) {
  isEdit.value = true
  form.value = {
    id: row.id, username: row.username, password: '',
    displayName: row.displayName || '', phone: row.phone || '', email: row.email || '',
    roleIds: row.roleIds ? [...row.roleIds] : []
  }
  showDialog.value = true
}

function openChangePwd(row) {
  pwdForm.value = { id: row.id, password: '', confirmPassword: '' }
  showPwdDialog.value = true
}

async function save() {
  if (!formRef.value) return
  const valid = await formRef.value.validate().catch(() => false)
  if (!valid) return
  saving.value = true
  try {
    if (isEdit.value) {
      const data = {
        displayName: form.value.displayName || undefined,
        phone: form.value.phone || undefined,
        email: form.value.email || undefined,
        roleIds: form.value.roleIds.length > 0 ? form.value.roleIds : []
      }
      await updateUser(form.value.id, data)
      ElMessage.success('用户已更新')
    } else {
      const data = {
        username: form.value.username,
        password: form.value.password || '123456',
        displayName: form.value.displayName,
        phone: form.value.phone || undefined,
        email: form.value.email || undefined,
        roleIds: form.value.roleIds.length > 0 ? form.value.roleIds : undefined
      }
      await createUser(data)
      ElMessage.success('用户已创建')
    }
    showDialog.value = false
    await fetchUsers()
  } catch (e) {
    ElMessage.error(isEdit.value ? '更新用户失败' : '创建用户失败')
  }
  saving.value = false
}

async function savePwd() {
  if (!pwdFormRef.value) return
  const valid = await pwdFormRef.value.validate().catch(() => false)
  if (!valid) return
  savingPwd.value = true
  try {
    await updateUser(pwdForm.value.id, { password: pwdForm.value.password })
    ElMessage.success('密码已修改')
    showPwdDialog.value = false
  } catch (e) {
    ElMessage.error('修改密码失败')
  }
  savingPwd.value = false
}

async function toggleStatus(row) {
  const action = row.isActive ? '停用' : '启用'
  try {
    await ElMessageBox.confirm(`确定${action}用户「${row.displayName}」吗？`, '提示', {
      confirmButtonText: '确定', cancelButtonText: '取消', type: 'warning'
    })
    await updateUser(row.id, { isActive: !row.isActive })
    ElMessage.success(`用户已${action}`)
    await fetchUsers()
  } catch (e) {
    if (e !== 'cancel') ElMessage.error(`${action}用户失败`)
  }
}

onMounted(() => {
  fetchUsers()
  fetchRoles()
})
</script>
```

# 第 4 章 扩展教程：自己加菜单 / 加功能 / 加模块

> 做完前三章你就掌握了骨架。本章教你自己往上加东西，**每个功能只需 3~4 处改动**。

## 4.1 加一个菜单（已有页面显示到侧边栏）

**菜单不是单独配出来的**，侧边栏由 `menuStore` 根据 router 的 `meta` 自动生成。所以加菜单 = 在路由表里加一行带 meta 的路由：

```js
// 在 router/index.js 的 MainLayout children 里加（path 小驼峰、禁止连字符）
{
  path: 'mymodule',                                   // 路由路径，小驼峰
  name: 'MyModule',                                   // PascalCase
  component: () => import('../views/mymodule/index.vue'),
  meta: { title: '我的模块', icon: 'Grid', roles: ['Admin'] }  // 侧边栏标题/图标/可见角色
}
```

保存后刷新，侧边栏自动出现"我的模块"。要点：
- `meta.title` **必须有**，没有则不显示菜单。
- `meta.hidden: true` 时不进侧边栏（详情页/创建页用）。
- `meta.roles` 为空数组表示全员可见。

## 4.2 加一个功能页面（列表 CRUD，照抄 user.vue 四步）

新页面 = 4 个位置的改动，顺序固定：

**① `api/index.js` 加接口**（照抄 Users 段）：

```js
export function getThings(params) { return request({ url: '/things', method: 'get', params }) }
export function createThing(data) { return request({ url: '/things', method: 'post', data }) }
export function updateThing(id, data) { return request({ url: `/things/${id}`, method: 'put', data }) }
export function deleteThing(id) { return request({ url: `/things/${id}`, method: 'delete' }) }
```

**② 新建 view**：`web/src/views/xxx/index.vue`，骨架照抄 user.vue——`el-table` 列表 + 新增/编辑 `el-dialog` + `el-form` 校验 + 保存/删除。复制 user.vue 改字段即可。

**③ router/index.js 挂路由**（见 4.1），带 `meta: { title, icon, roles }`。

**④ （可选）按钮权限**：若后端菜单里配了 `permissionCode`，按钮用 `v-permission="'xxx:create'"` 控制显示。

## 4.3 加一个模块（多页面二级菜单）

照抄 `system` 的嵌套结构：父路由用 `RouteView` 组件 + `children` 子路由，父级 `meta` 决定侧边栏一级菜单：

```js
{
  path: 'mymodule',
  component: RouteView,                        // 关键：二级容器
  redirect: '/mymodule/list',                  // 默认页
  meta: { title: '我的模块', icon: 'Grid', roles: ['Admin'] },
  children: [
    { path: 'list',    name: 'MyList',    component: () => import('../views/mymodule/list.vue'),    meta: { title: '列表', icon: 'List' } },
    { path: 'setting', name: 'MySetting', component: () => import('../views/mymodule/setting.vue'), meta: { title: '配置', icon: 'Setting' } }
  ]
}
```

侧边栏自动显示为"我的模块"下拉，含"列表/配置"两个子项。

## 4.4 按钮级权限 v-permission

```vue
<el-button v-permission="'building:create'">新增</el-button>
<el-button v-permission="['receipt:confirm', 'receipt:batch-confirm']">批量确认</el-button>
```

**原理**：登录后后端返回 `permissions` 数组，`userStore.hasPermission(code)` 检查，无权限时指令直接把 DOM 节点移除。前提：后端菜单表给该 path 配了对应 `permissionCode`。

## 4.5 前端约定清单（加功能必须遵守）

| 约定 | 说明 |
|---|---|
| 路由 path | 小驼峰，**禁止连字符**（`mymodule/list`，不是 `my-module`） |
| 路由 name | PascalCase（`MyModuleList`） |
| meta.title | 侧边栏/标题，必须填（无 title 不显示菜单） |
| meta.icon | Element Plus 图标名（全局已注册） |
| meta.hidden | true = 不进侧边栏（详情/创建页） |
| meta.roles | 角色白名单，空数组 = 全员 |
| localStorage | 只存 `token` / `userId` / `currentCompanyId`，**不存** user/permissions（防 XSS） |
| 接口函数 | 集中在 api/index.js，按模块分组注释 |
| 数据响应 | 拦截器已剥壳，组件直接拿业务 JSON；列表兼容 `Array.isArray(res) ? res : res.items` |

# 附录 B：常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| 请求 404 / 连接失败 | Vite 代理端口不对 / 后端没启动 | 检查 `vite.config.js` 的 `target` 端口 = 后端实际端口；启动后端 |
| 401 循环跳登录 | token 过期或无效 | 正常行为；重新登录。若一直跳，检查 `/api/auth/me` 是否可用 |
| 侧边栏不显示菜单 | `meta.title` 缺失，或 roles 不含当前用户角色 | 给路由补 `meta.title`；确认当前用户有对应角色/权限码 |
| `v-permission` 按钮不显示 | 后端 permissions 里没有该权限码 | 确认后端菜单表给该 path 配了对应 `permissionCode`，并重新登录刷新 permissions |
| 登录成功但列表页报错 | 接口字段名对不上 | 用浏览器 Network 看响应 JSON，比对 api 函数返回的字段 |
| 改动代码不生效 | Vite 缓存 | 刷新页面；必要时 `Ctrl+Shift+R` 强刷 |
