# 前端框架搭建与调用完整案例（以 web 站点为例）

> **这份文档是什么**
>
> 本文以本仓库 `web/` 站点为蓝本，带你**从空目录开始、按先后顺序手写**一套可运行的 Vue 3 前端框架，
> 然后在这个框架上**完整实现一个业务模块（房型管理）**，把"框架是怎么被调用起来的"这条链路走通。
>
> **和《前端从0到1搭建指南.md》的区别**
>
> | | 搭 建 指 南 | 本 案 例 |
> |---|---|---|
> | 骨架范围 | 全量复现（含多公司视角、跨标签页广播、通知轮询、后端权限码映射） | **精简骨架**：保留分层架构与全部约定，去掉进阶特性 |
> | 重点 | "文件怎么建" | "文件怎么建" + **"调用链怎么走"**（第 2 章） |
> | 示例模块 | 用户管理（照抄 `web/` 已有页面） | **房型管理**（List + CRUD，接口真实存在，可直接运行） |
> | 篇幅 | 57 KB | 更短，但每条链路都讲透 |
>
> **怎么用这份文档**
>
> 1. 第 0 章：建环境、装包（只有命令，照着敲）
> 2. 第 1 章：**按顺序**新建 18 个文件，每个文件都是完整代码（照着手打）
> 3. 第 2 章：停下来读一遍调用链，理解"谁调用谁"
> 4. 第 3 章：新增一个业务模块，验证你确实学会了
>
> ⚠️ 本文所有前端代码都对接**本仓库已有的后端**（`src/RBS.Api`，默认 `http://localhost:5178`），
> 不需要你写一行后端代码。第 3 章的房型接口是后端已经提供的，做完就能看到真实数据。

## 0.2 创建项目

```bash

# 2. 进入目录
cd web-learn

# 3. 装脚手架自带依赖（vue / vite / @vitejs/plugin-vue）
npm install
```


打开 `http://localhost:5173`，看到 Vite 默认欢迎页 → 环境 OK，继续。

## 1.2 逐步创建

### 第 1 步 `index.html`

> 覆盖脚手架生成的同名文件。它只干一件事：提供一个 `<div id="app">` 给 Vue 挂载。

```html
<!doctype html>
<html lang="zh-CN">
  <head>
    <meta charset="UTF-8" />
    <link rel="icon" type="image/svg+xml" href="/vite.svg" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>房屋租赁收租结算系统</title>
  </head>
  <body>
    <div id="app"></div>
    <script type="module" src="/src/main.js"></script>
  </body>
</html>
```

**关键点**：`<script type="module" src="/src/main.js">` 是入口脚本，Vite 从这里开始打包。

---

### 第 2 步 `vite.config.js`

> 覆盖脚手架生成的文件。加两件事：`@` 别名 + `/api` 开发代理。

```js
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import { fileURLToPath, URL } from 'node:url'

// https://vite.dev/config/
export default defineConfig({
  plugins: [vue()],
  resolve: {
    alias: {
      // 让 import ... from '@/xxx' 指向 src/xxx（本项目两种写法混用：'@/api' 和 '../../api/index' 都能跑）
      '@': fileURLToPath(new URL('src', import.meta.url))
    }
  },
  server: {
    port: 5173,
    proxy: {
      // ★ 关键：前端一律请求 /api/**，由 Vite 代理转发到后端，前端不需要处理跨域
      '/api': {
        target: 'http://localhost:5178',   // ← 改成你后端实际端口
        changeOrigin: true
      }
    },
    historyApiFallback: true   // history 路由模式：刷新子页面时回退到 index.html
  }
})
```

**为什么要代理**：前端跑在 `5173`，后端在 `5178`，浏览器直接请求就是跨域。
代理之后，浏览器只看到同源的 `/api/...`，跨域问题在开发服务器层面被消化掉了。
**生产环境**由 nginx 做同一件事（见 `web/nginx.conf` 的 `location /api/`）。

### 第 5 步 `src/api/request.js`

> 新建文件。**整个网络层的地基**：一个配好拦截器的 axios 实例。
> 它负责三件事：① 自动带 token；② 自动剥壳 `response.data`；③ 统一错误提示。

```js
/**
 * =========================================================================
 *  axios HTTP 客户端
 *
 *  三件事：
 *    1. 请求拦截器 — 自动注入 JWT Token
 *    2. 响应拦截器 — 自动剥壳 response.data，按 HTTP 状态码统一提示
 *    3. handleApiError — 供组件在 catch 中调用的统一错误提示函数
 * =========================================================================
 */

import axios from 'axios'
import { ElMessage } from 'element-plus'
import router from '../router'

// ---------------------------------------------------------------------------
// axios 实例
//   baseURL: '/api'  → 配合 vite.config.js 的 proxy，转发到 localhost:5178
//   timeout: 30s     → 超时自动断开，避免请求悬挂
// ---------------------------------------------------------------------------
const request = axios.create({
  baseURL: '/api',
  timeout: 30000
})

// ===========================================================================
// handleApiError — 组件层统一错误处理
//
// 为什么要有它（而不是拦截器全包）：
//   拦截器只能给"通用"提示；组件知道上下文，能给出"提交失败""加载列表失败"这种
//   更准确的兜底文案。但两者都可能弹消息，所以这里先 ElMessage.closeAll()
//   清掉拦截器弹的，再弹自己的 —— 用户最终只看到一条最贴切的消息。
//
// 用法：
//   try { await createRoomType(data) }
//   catch (e) { handleApiError(e, '创建房型失败') }
//
// @param {Error}  e            catch 到的 AxiosError
// @param {string} defaultMsg   后端没给具体消息时的兜底文案
// ===========================================================================
export function handleApiError(e, defaultMsg = '操作失败') {
  ElMessage.closeAll()
  const status = e?.response?.status
  const data = e?.response?.data
  if (data?.code) {
    // 后端返回的业务错误结构 { code, message }
    ElMessage.error(data.message || defaultMsg)
  } else if (status === 500) {
    ElMessage.error('系统错误，请稍后重试')   // 不把服务端细节暴露给用户
  } else {
    ElMessage.error(data?.message || data?.error || defaultMsg)
  }
}

// ===========================================================================
// 请求拦截器 — 发出前统一加工 config
// ===========================================================================
request.interceptors.request.use(
  config => {
    // 从 localStorage 取 token 塞进 Authorization 头
    // token 由 store/user.js 在登录成功后写入、登出时清除
    const token = localStorage.getItem('token')
    if (token) {
      config.headers.Authorization = `Bearer ${token}`
    }
    // 想加统一参数（如 companyId、租户标识）就在这儿加：
    // config.params = { ...(config.params || {}), companyId }
    return config
  },
  error => Promise.reject(error)
)

// ===========================================================================
// 响应拦截器 — 收到响应后统一处理
// ===========================================================================
request.interceptors.response.use(
  // ---------- 成功：剥壳 ----------
  // 组件里 `const data = await getFoo()` 拿到的就是后端 JSON 本体，
  // 不需要再写 `res.data.data`。
  response => response.data,

  // ---------- 失败：按状态码分类 ----------
  error => {
    if (error.response) {
      switch (error.response.status) {
        case 401:   // 未登录 / token 过期
          localStorage.removeItem('token')
          localStorage.removeItem('userId')
          router.push('/login')
          ElMessage.closeAll()
          ElMessage.error('登录已过期，请重新登录')
          break
        case 403:   // 已登录但没权限
          ElMessage.error(error.response.data?.message || '没有权限执行此操作，请联系管理员')
          window.dispatchEvent(new CustomEvent('permission-denied', {
            detail: { url: error.config?.url, method: error.config?.method }
          }))
          break
        case 404:
          ElMessage.error('请求的资源不存在')
          break
        case 500:
          ElMessage.error('服务器错误')
          break
        default:
          ElMessage.error(error.response.data?.message || '请求失败')
      }
    } else {
      // 没有 response：网络断了 / 后端没启动 / 被 CORS 拦了
      ElMessage.error('网络连接失败')
    }
    // 继续往外抛，让组件的 catch 也能拿到（组件里再决定显示什么文案）
    return Promise.reject(error)
  }
)

export default request
```

### 第 7 步 `src/store/user.js`

> 新建文件。**全框架最重要的 store**：token、用户资料、权限码、登录登出。

```js
/**
 * =========================================================================
 *  用户状态管理 (useUserStore)
 *
 *  职责：
 *    1. 登录 / 登出
 *    2. 页面刷新后恢复登录态（loadUserProfile）
 *    3. 提供权限判断 hasPermission（给 v-permission 指令用）
 *
 *  安全约定（照抄原项目）：
 *    - localStorage 只存 token + userId（用于恢复登录态）
 *    - 用户资料 / 权限码只放 Pinia 内存，页面刷新后向后端重新拉
 *      → 避免这些敏感信息被 XSS 读到 / 篡改
 * =========================================================================
 */
import { defineStore } from 'pinia'
import { ref, computed } from 'vue'
import { login as loginApi, getMyProfile } from '../api/index'

export const useUserStore = defineStore('user', () => {
  // ---------------------------------------------------------------------------
  // 状态
  // ---------------------------------------------------------------------------
  /** 登录令牌（从 localStorage 恢复） */
  const token = ref(localStorage.getItem('token') || '')
  /** 用户 ID（从 localStorage 恢复） */
  const userId = ref(localStorage.getItem('userId') || '')
  /** 用户资料（仅内存） */
  const user = ref({})
  /** 权限码数组（仅内存），如 ['roomtype:create', 'system:roomtypeedit'] */
  const permissions = ref([])
  /** 用户资料是否已从后端加载，防止重复请求 */
  const profileLoaded = ref(false)

  // ---------------------------------------------------------------------------
  // 计算属性
  // ---------------------------------------------------------------------------
  /** 角色编码数组，如 ['Admin'] —— 菜单按这个过滤 */
  const roles = computed(() =>
    (user.value.roles || []).map(r => (typeof r === 'string' ? r : r.code)).filter(Boolean)
  )

  /** 是否超级管理员 —— 超管看全部菜单 */
  const isSuperAdmin = computed(() => user.value.isSuperAdmin === true)

  // ---------------------------------------------------------------------------
  // setUserData — login 和 loadUserProfile 共用的"填数据"逻辑
  //
  // 后端两种响应形状都要兼容：
  //   登录：{ token, user: {...}, roles: [...], permissions: [...] }
  //   我的资料：{ id, username, roles: [...], permissions: [...] }  ← 扁平结构
  // ---------------------------------------------------------------------------
  function setUserData(payload, tokenVal) {
    const userData = payload.user || payload
    if (tokenVal) token.value = tokenVal
    // roles 可能挂在顶层，也可能在 user 里面
    user.value = { ...userData, roles: userData.roles || payload.roles || [] }
    permissions.value = payload.permissions || []
    profileLoaded.value = true
  }

  // ---------------------------------------------------------------------------
  // login — 登录
  // ---------------------------------------------------------------------------
  async function login(credentials) {
    const res = await loginApi(credentials)
    const tokenVal = res.token || res.accessToken

    setUserData(res, tokenVal)

    // 只有 token 和 userId 落 localStorage
    localStorage.setItem('token', tokenVal)
    localStorage.setItem('userId', String(res.user?.id || res.id || ''))

    return res
  }

  // ---------------------------------------------------------------------------
  // loadUserProfile — 页面刷新后恢复登录态
  // 由 MainLayout 的 onMounted 调用；token 过期时接口 401，
  // 拦截器已经跳登录页了，这里只需清干净本地状态。
  // ---------------------------------------------------------------------------
  async function loadUserProfile() {
    if (!token.value || profileLoaded.value) return
    try {
      const res = await getMyProfile()
      setUserData(res, token.value)
    } catch (e) {
      logout()
      throw e
    }
  }

  // ---------------------------------------------------------------------------
  // logout — 登出，清空内存 + localStorage
  // ---------------------------------------------------------------------------
  function logout() {
    token.value = ''
    userId.value = ''
    user.value = {}
    permissions.value = []
    profileLoaded.value = false
    localStorage.removeItem('token')
    localStorage.removeItem('userId')
  }

  // ---------------------------------------------------------------------------
  // hasPermission — 权限码判断，v-permission 指令和页面里都会调
  // ---------------------------------------------------------------------------
  function hasPermission(code) {
    if (!code) return true
    return permissions.value.includes(code)
  }

  return {
    // state
    token, userId, user, permissions, profileLoaded,
    // getters
    roles, isSuperAdmin,
    // actions
    login, loadUserProfile, logout, hasPermission
  }
})
```

### 第 9 步 `src/store/menu.js`

> 新建文件。**侧边栏菜单不是手写的，而是从路由表推导出来的** —— 这是本框架省事的关键设计。
>
> 规则：路由 `meta.title` 决定菜单文字，`meta.icon` 决定图标，`meta.roles` 决定谁能看见，
> `meta.hidden: true` 表示"是路由但不上菜单"（详情页、创建页都这样）。

```js
/**
 * =========================================================================
 *  侧边栏菜单 (useMenuStore)
 *
 *  设计思想：
 *    菜单 = 路由表的一个视图。加一个页面只需在 router/index.js 加一条路由，
 *    菜单自动出现，不用维护两份配置（这是很多项目最容易忘记同步的地方）。
 *
 *  可见性规则（按优先级）：
 *    1. meta.hidden === true        → 永不显示
 *    2. 超管                        → 全部显示
 *    3. meta.scope === 'System'     → 仅超管
 *    4. meta.roles 有值             → 用户角色命中任一才显示
 *    5. 没有 roles                  → 公共菜单，所有人可见
 * =========================================================================
 */
import { defineStore } from 'pinia'
import { ref } from 'vue'
import { useUserStore } from './user'

export const useMenuStore = defineStore('menu', () => {
  /** 已构建好的侧边栏菜单树 */
  const sidebarMenus = ref([])
  /** 缓存路由表，供 rebuildMenus 复用 */
  let cachedRoutes = []

  /**
   * 初始化：传入 MainLayout 的子路由数组
   * 必须在用户资料加载完成后调用，否则角色是空的，菜单会全被过滤掉
   */
  function initFromRoutes(routes) {
    cachedRoutes = routes || []
    rebuildMenus()
  }

  /** 重新构建菜单（角色变化、权限刷新后调用） */
  function rebuildMenus() {
    const userStore = useUserStore()
    sidebarMenus.value = buildMenusFromRoutes(cachedRoutes, userStore)
  }

  /** 规范化路径：确保以 / 开头、不以 / 结尾（父路径拼接时需要） */
  function normalizePath(p) {
    let s = (p || '').startsWith('/') ? p : '/' + (p || '')
    if (s.length > 1 && s.endsWith('/')) s = s.slice(0, -1)
    return s
  }

  /** 单个菜单项对当前用户是否可见 */
  function isMenuVisible(meta, userStore) {
    if (meta.hidden) return false
    if (userStore.isSuperAdmin) return true
    if (meta.scope === 'System') return false
    if (meta.roles && meta.roles.length > 0) {
      return meta.roles.some(r => userStore.roles.includes(r))
    }
    return true
  }

  /** 把路由表递归翻译成菜单树 */
  function buildMenusFromRoutes(routes, userStore) {
    const result = []

    for (const route of routes) {
      const meta = route.meta || {}
      if (meta.hidden) continue
      if (meta.scope === 'System' && !userStore.isSuperAdmin) continue

      const fullPath = normalizePath(route.path || '')

      // ---------- 先处理子路由 ----------
      let visibleChildren = []
      if (route.children && route.children.length > 0) {
        for (const child of route.children) {
          const childMeta = child.meta || {}
          if (childMeta.hidden) continue
          if (childMeta.scope === 'System' && !userStore.isSuperAdmin) continue
          if (!childMeta.title) continue
          if (!isMenuVisible(childMeta, userStore)) continue

          visibleChildren.push({
            id: child.path || child.name,
            name: childMeta.title,
            fullPath: normalizePath((route.path || '') + '/' + (child.path || '')),
            icon: childMeta.icon || '',
            children: []
          })
        }
      }

      // ---------- 父路由可见性 ----------
      // 两种情况父亲要留下：自己有权限，或者有至少一个孩子可见（二级菜单组的典型情况）
      const parentVisible = isMenuVisible(meta, userStore)
      if (!parentVisible && visibleChildren.length === 0) continue
      if (!meta.title && visibleChildren.length === 0) continue

      if (meta.title || visibleChildren.length > 0) {
        result.push({
          id: route.path || route.name,
          name: meta.title || route.name || '',
          fullPath,
          icon: meta.icon || '',
          children: visibleChildren
        })
      }
    }

    return result
  }

  return { sidebarMenus, initFromRoutes, rebuildMenus }
})
```

### 第 10 步 `src/directives/permission.js`

> 新建文件。**按钮级权限**：没有权限码的按钮直接从 DOM 里移除（比 `disabled` 更彻底，用户连按钮都看不见）。

```js
/**
 * v-permission 自定义指令 —— 按钮级权限
 *
 * 用法：
 *   <el-button v-permission="'system:roomtypecreate'">新增</el-button>
 *   <el-button v-permission="['a:create', 'a:edit']">任一命中即可见</el-button>
 *   <template v-permission="'a:delete'"> ...多个元素... </template>
 *
 * 说明：
 *   权限码来自后端 /api/auth/me 返回的 permissions 数组（登录时由 /auth/login 一起返回）。
 *   超管的 permissions 包含全部权限码，所以超管永远看得到。
 *   注意：这只是"界面友好"，真正的拦截必须由后端做（前端代码任何人都能改）。
 */
import { useUserStore } from '@/store/user'

export default {
  mounted(el, binding) {
    const { value } = binding
    if (!value) return

    const codes = Array.isArray(value) ? value : [value]
    if (!codes.length) return

    const userStore = useUserStore()
    const allowed = codes.some(code => userStore.hasPermission(code))

    if (!allowed) {
      el.parentNode && el.parentNode.removeChild(el)
    }
  }
}
```

> ⚠️ 注意 `mounted` 只在元素挂载时执行一次。所以**不要在 `v-permission` 之外还依赖按钮的动态出现**；
> 如果权限是异步加载完之后才知道的（本项目就是），必须保证页面渲染时 `permissions` 已经就位 ——
> 本框架用 `MainLayout` 先 `await loadUserProfile()` 再渲染 `<router-view />` 的方式保证这一点。

```vue
<script setup>
import { ref, reactive } from 'vue'
import { useRouter } from 'vue-router'
import { ElMessage } from 'element-plus'
import { User, Lock } from '@element-plus/icons-vue'
import { useUserStore } from '../../store/user'

const router = useRouter()
const userStore = useUserStore()

const formRef = ref(null)
const loading = ref(false)

const loginForm = reactive({ username: '', password: '' })

const rules = {
  username: [{ required: true, message: '请输入用户名', trigger: 'blur' }],
  password: [{ required: true, message: '请输入密码', trigger: 'blur' }]
}

async function handleLogin() {
  // 1) 表单校验
  const valid = await formRef.value.validate().catch(() => false)
  if (!valid) return

  // 2) 调 store 的 login（内部会调 api/index.js 的 login → axios）
```

### 第 15 步 `src/views/redirect/index.vue`

> 新建文件。**一个小技巧**：需要在"当前页面原地刷新"时（比如切换公司视角、切换身份），
> 直接 `router.push(相同路径)` 不会重新渲染组件，所以要绕一下 `/redirect/xxx` 再跳回来。

```vue
<template>
  <router-view />
</template>

<script setup>
import { onMounted } from 'vue'
import { useRoute, useRouter } from 'vue-router'

const route = useRoute()
const router = useRouter()

onMounted(() => {
  // 路由参数 :path(.*) 是个数组，用 / 拼回去
  const path = route.params.path
  if (path) {
    router.replace('/' + (Array.isArray(path) ? path.join('/') : path))
  } else {
    router.replace('/dashboard')
  }
})
</script>
```

**注意三点**：
1. `<HomeFilled />` / `<ArrowDown />` / `<SwitchButton />` 在模板里直接用，是因为 `main.js` 会**全局注册所有 Element Plus 图标**（第 18 步），不用在 script 里 import。
2. `Fold` / `Expand` 作为 `:icon` 的值传给按钮，属于 script 里的变量引用，所以必须 import。
3. **`<router-view v-if="userStore.profileLoaded" />` 这个 v-if 是个关键坑**，详见下面这条：

> ### 为什么必须写 `v-if="userStore.profileLoaded"`
>
> Vue 的挂载顺序是 **子组件 → 父组件**：`<router-view>` 里的业务页面会**先**挂载，
> `MainLayout` 自己的 `onMounted`（也就是 `await loadUserProfile()`）**后**执行。
>
> 而 `v-permission` 指令只在 `mounted` 钩子里判断一次权限。于是硬刷新业务页时的时间线是：
>
> ```
> 刷新 /system/roomtypes
>   ├─ MainLayout 渲染 → <router-view> → 房型页面开始挂载
>   │     └─ v-permission.mounted 执行 → permissions 还是 []（资料没加载）
>   │           └─ 判定"无权限" → 把「新增」「编辑」「删除」按钮全部 remove 掉  ✗
>   └─ MainLayout.onMounted → await loadUserProfile() → permissions 终于就位
>         └─ 但指令不会重跑（没有 updated 钩子），按钮再也回不来了
> ```
>
> 症状很好认：**从别的页面点进来一切正常，唯独在业务页按 F5 刷新后按钮全没了。**
> 修法就是上面那个 `v-if` —— 权限没就位就不渲染业务页面。
>
> 如果你自己在别的项目里也用了"指令式权限 + 父组件异步加载用户"，务必检查这一点。

### 第 17 步 `src/router/index.js`

> 新建文件。**路由表是全项目的"地图"**：它同时决定了页面层级、侧边栏菜单、权限范围。

```js
/**
 * =========================================================================
 *  路由表（集中式）
 *
 *  结构：
 *    /redirect/:path  刷新兜底
 *    /login           登录页（无 token 唯一可访问）
 *    /                MainLayout（主框架）
 *      /dashboard     仪表盘
 *      /system        系统设置（二级菜单组，用 RouteView 承载子路由）
 *        /system/roomtypes  房型管理（第 3 章加）
 *    /:pathMatch(.*)  404
 *
 *  meta 约定（非常重要，菜单和权限全靠它）：
 *    title   中文标题，显示在侧边栏
 *    icon    Element Plus 图标名（字符串，如 'Grid'）
 *    roles   角色白名单数组，空/不写 = 所有人可见
 *    hidden  true = 有路由但不上菜单（详情页/创建页）
 *    scope   'System' = 仅超管可见
 *
 *  命名规范：
 *    path 全小写无连字符（roomtypes，不是 room-types）
 *    name PascalCase（RoomTypeList）
 * =========================================================================
 */
import { createRouter, createWebHistory } from 'vue-router'
import RouteView from '../layout/RouteView.vue'
import NotFound from '../views/error/NotFound.vue'

const routes = [
  // ---------- 刷新兜底：/redirect/当前路径 → 回到当前路径并重建组件 ----------
  {
    path: '/redirect/:path(.*)',
    component: () => import('../views/redirect/index.vue'),
    meta: { hidden: true }
  },

  // ---------- 登录页 ----------
  {
    path: '/login',
    name: 'Login',
    component: () => import('../views/login/index.vue'),
    meta: { hidden: true }
  },

  // ---------- 主框架 ----------
  {
    path: '/',
    component: () => import('../layout/MainLayout.vue'),
    redirect: '/dashboard',
    children: [
      {
        path: 'dashboard',
        name: 'Dashboard',
        component: () => import('../views/dashboard/index.vue'),
        meta: { title: '仪表盘', icon: 'DataAnalysis' }
      },

      // =====================================================================
      // 二级菜单组示例：系统设置
      //   父路由 component 用 RouteView（只是 <router-view /> 占位），
      //   子路由渲染在它的位置上；菜单里会自动变成一个可展开的分组。
      // =====================================================================
      {
        path: 'system',
        component: RouteView,
        redirect: '/system/roomtypes',   // 点父菜单时落到第一个子页
        meta: { title: '系统设置', icon: 'Setting', roles: ['Admin'] },
        children: [
          // （第 3 章在这里追加房型管理）
        ]
      }
    ]
  },

  // ---------- 404：必须放最后 ----------
  {
    path: '/:pathMatch(.*)*',
    name: 'NotFound',
    component: NotFound,
    meta: { title: '页面不存在', hidden: true }
  }
]

const router = createRouter({
  history: createWebHistory(),
  routes
})

/**
 * 全局前置守卫 —— 只做登录态检查
 *
 *  1. 无 token 且不是去登录页 → 踢到 /login
 *  2. 有 token 却要去登录页   → 送进 /dashboard
 *  3. 其他                    → 放行
 *
 *  为什么守卫里不做角色/权限判断？
 *    因为刷新页面时 localStorage 里只有 token，用户资料还没拉回来，
 *    此刻判断角色一定是错的。角色相关的判断放在 MainLayout 里，
 *    等 loadUserProfile() 完成后再说。
 */
router.beforeEach((to, from, next) => {
  const token = localStorage.getItem('token')
  if (to.path !== '/login' && !token) {
    next('/login')
  } else if (to.path === '/login' && token) {
    next('/dashboard')
  } else {
    next()
  }
})

export default router
```

```
  ├─ app.use(ElementPlus, { locale: zhCn })
  ├─ app.use(createPinia())       （能用 store 的原因）
  └─ app.use(router) → app.mount('#app')
        │
        ▼
App.vue  <router-view />
        │
        ▼
router.beforeEach（守卫）
   ├─ 没有 token  → 去 /login        → 渲染 views/login/index.vue
   └─ 有 token    → 匹配 '/' → 渲染 layout/MainLayout.vue
                                    │
                                    ▼
                        MainLayout.onMounted
                          ├─ await userStore.loadUserProfile()
                          │      └─ GET /api/auth/me
                          │            └─ 结果写入 user / permissions
                          └─ menuStore.initFromRoutes(MainLayout 的 children)
                                 └─ 用 userStore.roles 过滤 → sidebarMenus
                                    │
                                    ▼
                        MainLayout 模板渲染完成
                          ├─ 侧边栏：v-for menuStore.sidebarMenus
                          └─ 内容区：<router-view v-if="profileLoaded" />
                                 ↑ 资料没就位就不渲染业务页面（原因见第 16 步）
                                  就位后 → 渲染 dashboard/index.vue
```

**记住这条链的价值**：菜单为空 / 用户名不显示 / 按钮权限失效，全部落在这个顺序里。
"必须在 `loadUserProfile()` 之后才有权限和角色" 是整条链的核心约束。

## 2.2 登录链

以"点击登录按钮"为例，看一次完整的**上行 + 下行**：

```
[登录页] 点击"登录"
   └─→ handleLogin()
         ├─ formRef.validate()            表单校验失败就地返回
         └─→ userStore.login({username, password})          【store/user.js】
               └─→ loginApi(credentials)                    【api/index.js】
                     └─→ request({ url:'/auth/login', method:'post', data })   【api/request.js】
                           ├─ 请求拦截器：localStorage 有 token 就加 Authorization
                           └─→ HTTP POST /api/auth/login
                                 └─→ Vite proxy 转发 → http://localhost:5178/api/auth/login
   ┌─────────────────────── 后端处理，返回 JSON ───────────────────────┐
   │ { token, user:{...}, roles:[...], permissions:[...] }            │
   └──────────────────────────────────────────────────────────────────┘
                                 │
              响应拦截器：response => response.data   ← 剥壳
                                 │
              回到 userStore.login()
                 ├─ setUserData(res, token)
                 │     ├─ user.value  = res.user
                 │     ├─ permissions.value = res.permissions   ← 按钮权限的源头
                 │     └─ profileLoaded.value = true
                 └─ localStorage.setItem('token' / 'userId')      ← 只存这两个
                                 │
              回到登录页：router.push('/dashboard')
                                 │
              守卫放行（有 token）→ 渲染 MainLayout → 走 2.1 的启动链后半段
```

**关键理解**：`permissions` 是**登录时随响应一起拿到的**，不是另外请求的。
所以只要登录成功，按钮权限立刻可用（`v-permission` 在 mounted 时就能查到）。

## 2.3 请求链

任何一次接口调用都经过同一条流水线，这是"组件里只写一行 await"的前提：

```
组件 await getFoo(params)
        │
        ▼
api/index.js   把参数翻译成 URL + method（唯一声明处）
        │
        ▼
api/request.js 请求拦截器
        │         · 注入 Authorization: Bearer <token>
        │         · （原项目这里还会注入 companyId）
        ▼
axios → /api/foo → Vite proxy → 后端
        │
        ├── HTTP 2xx ──→ 响应拦截器：return response.data    → 组件拿到 JSON 本体
        │
        └── HTTP 4xx/5xx ──→ 响应拦截器分类弹消息 + reject
                                     │
                                     ▼
                            组件的 catch (e)
                                     │
                                     └─→ handleApiError(e, '加载失败')
                                           · 先 ElMessage.closeAll() 清掉拦截器的消息
                                           · 再弹最贴切的业务文案
```

**两级错误处理的分工**（这是本项目一个值得学的设计）：

| 层 | 职责 | 好处 |
|---|---|---|
| 拦截器 | 网络/HTTP 层面的通用提示（401 跳登录、500 提示服务器错误） | 组件不用每处都写，兜底不遗漏 |
| 组件 `catch` + `handleApiError` | 业务语境的精确文案（"创建房型失败"） | 用户看到的是人话，且只有一条消息 |

## 2.4 菜单链

```
router/index.js 的 routes（唯一数据源）
        │  MainLayout 取 children
        ▼
menuStore.initFromRoutes(children)
        │
        ▼
buildMenusFromRoutes(routes, userStore)
        │   对每个路由：
        │     meta.hidden === true        → 跳过
        │     meta.scope === 'System'     → 非超管跳过
        │     超管                          → 全要
        │     meta.roles 命中用户 roles    → 要
        │     没有 roles                   → 公共，要
        │   有可见子路由的父路由             → 也要（变成可展开的分组）
        ▼
sidebarMenus（菜单树）
        │
        ▼
MainLayout 模板 v-for 渲染
        │  有 children → <el-sub-menu>
        │  没有        → <el-menu-item :index="fullPath">
        ▼
el-menu 的 router 模式：点击 = router.push(index)
```

**结论**：**加页面只需加一条路由**，菜单自动出现。这就是第 3 章只需要改两个文件的根本原因。

## 2.5 权限链

权限有**两层**，别混淆：

| 层次 | 控制什么 | 实现位置 | 后端是否强制 |
|---|---|---|---|
| 菜单级 | 某个页面对用户是否可见 | `meta.roles` / 后端权限码 | 后端接口自身要鉴权 |
| 按钮级 | 页面内某个按钮是否可见 | `v-permission="'权限码'"` | 后端接口自身要鉴权 |

```
登录/刷新 → permissions: ['system:roomtypecreate', 'system:roomtypeedit', ...]   （来自后端）
                        │
                        ├─→ store.hasPermission('system:roomtypecreate')
                        │        │
                        │        └─→ v-permission 指令 mounted 时调用
                        │              ├─ 命中 → 按钮留在 DOM
                        │              └─ 不命中 → el.parentNode.removeChild(el)  ← 直接删掉
                        │
                        └─→ 后端 403 ──→ 响应拦截器弹"没有权限执行此操作"
```

> ⚠️ **`v-permission` 只在 `mounted` 执行一次，是"渲染时刻"的快照。**
> 而子组件的 `onMounted` 早于父组件 —— 不处理的话，硬刷新业务页时业务页面会
> 在权限加载完之前挂载，有权限的按钮也会被误删。
> 本框架用 `MainLayout` 里的 `<router-view v-if="userStore.profileLoaded" />` 兜住这一步（见第 16 步的说明）。

## 2.6 页面链（CRUD 页面的统一骨架）

本项目所有列表页都是同一个骨架，照着写就不会跑偏：

```
views/xxx/index.vue
├── <template>
│   ├── .page-header      标题 + 主操作按钮（新增，通常带 v-permission）
│   ├── .search-bar       查询条件 + 查询/重置按钮
│   ├── el-card > el-table 列表（v-loading、:data、操作列）
│   └── el-dialog + el-form 新增/编辑弹窗（同一个弹窗，靠 isEdit 区分）
│
└── <script setup>
    ├── 状态：loading / list / keyword / showDialog / isEdit / saving / form / rules
    ├── fetchList()    GET  列表 → list.value
    ├── openCreate()   清空 form，isEdit=false，开弹窗
    ├── openEdit(row)  用 row 填 form，isEdit=true，开弹窗
    ├── save()         validate → POST/PUT → 关弹窗 → 重新 fetchList
    ├── toggleStatus() 二次确认 → PUT 局部字段 → fetchList
    ├── handleDelete() 二次确认 → DELETE → fetchList
    └── onMounted(fetchList)
```

**三个固定习惯**：
1. **任何写操作成功后都重新 `fetchList()`**，不手工改本地数组（避免数据不一致）。
2. **二次确认用 `ElMessageBox.confirm`**，`catch` 里判断 `e !== 'cancel'` 才算真失败。
3. **`catch` 统一走 `handleApiError(e, '具体文案')`**。

## 3.1 后端接口契约

后端代码：`src/RBS.Api/Controllers/RoomTypesController.cs`。
所有响应都是 **camelCase**（`Program.cs` 里配了 `JsonNamingPolicy.CamelCase`）。

| 功能 | 方法 | 路径 | 请求体 | 响应 |
|---|---|---|---|---|
| 列表 | GET | `/api/roomtypes` | 无 | `[{ id, name, description, isActive }]`（**数组，不分页**） |
| 新增 | POST | `/api/roomtypes` | `{ name, description? }` | `{ id, name, description, isActive }` |
| 修改 | PUT | `/api/roomtypes/{id}` | `{ name?, description?, isActive? }` | 204 No Content（响应拦截器返回 `''`） |
| 删除 | DELETE | `/api/roomtypes/{id}` | 无 | 204 No Content |
| 详情 | GET | `/api/roomtypes/{id}` | 无 | ⚠️ **控制器暂未暴露**，见 3.9 |

DTO 字段（`src/RBS.Application/DTOs/Property/RoomTypeDto.cs`）：

```csharp
RoomTypeDto        { Guid Id; string Name; string? Description; bool IsActive; }
CreateRoomTypeRequest { string Name; string? Description; }          // 只能给这两个
UpdateRoomTypeRequest { string? Name; string? Description; bool? IsActive; }  // 全是可选
```

> 注意 204 的坑：项目里有 `catch { ElMessage.error('更新失败') }` 这种写法，
> 如果只用 `try/catch` 判断成败，204 是成功（不会进 catch）。
> **判断成功要靠"没抛异常"，不能靠响应体里有没有字段。**

```vue
<template>
  <div>
    <!-- ---------- 1. 页头：标题 + 主操作按钮（带权限码） ---------- -->
    <div class="page-header">
      <h2>房型管理</h2>

    <!-- ---------- 3. 表格 ---------- -->
    <el-card shadow="never">
      <el-table :data="filteredList" stripe v-loading="loading" style="width:100%">
        <el-table-column type="index" label="#" width="60" />

        <el-table-column prop="description" label="说明" min-width="240" show-overflow-tooltip />
        <el-table-column label="状态" width="100">

          <el-empty description="暂无房型数据" />

    <!-- ---------- 4. 新增 / 编辑弹窗（同一个，用 isEdit 区分） ---------- -->
    <el-dialog
      v-model="showDialog"
      :title="isEdit ? '编辑房型' : '新增房型'"
      width="520px"
      draggable
    >
      <el-form ref="formRef" :model="form" :rules="rules" label-width="90px">
        <el-form-item label="房型名称" prop="name">
          <el-input v-model="form.name" placeholder="如：一室一厅" maxlength="50" show-word-limit />
        </el-form-item>

        <el-button @click="showDialog = false">取消</el-button>
        <el-button type="primary" :loading="saving" @click="save">保存</el-button>
      </template>
    </el-dialog>

<script setup>
import { ref, computed, onMounted } from 'vue'
import { ElMessage, ElMessageBox } from 'element-plus'
import { Search, Refresh } from '@element-plus/icons-vue'
import { getRoomTypes, createRoomType, updateRoomType, deleteRoomType } from '../../api/index'
import { handleApiError } from '../../api/request'

// ---------------------------------------------------------------------------
// 列表状态
// ---------------------------------------------------------------------------
const loading = ref(false)
const list = ref([])
const keyword = ref('')

// ---------------------------------------------------------------------------
// 弹窗状态
// ---------------------------------------------------------------------------
const showDialog = ref(false)
const isEdit = ref(false)
const saving = ref(false)
const formRef = ref(null)

/** 表单数据：id 为 null 表示新增 */
const form = ref({ id: null, name: '', description: '' })

const rules = {
  name: [{ required: true, message: '请输入房型名称', trigger: 'blur' }]
}

// ---------------------------------------------------------------------------
// 本地过滤
// 说明：/api/roomtypes 不支持关键字参数，所以在这里过滤。
// 如果接口支持 keyword/page 参数，请看 3.8 的分页写法（把过滤交给后端）。
// ---------------------------------------------------------------------------
const filteredList = computed(() => {
  const kw = keyword.value.trim().toLowerCase()
  if (!kw) return list.value
  return list.value.filter(r =>
    (r.name || '').toLowerCase().includes(kw) ||
    (r.description || '').toLowerCase().includes(kw)
  )
})

// ---------------------------------------------------------------------------
// fetchList — 拉列表
// ---------------------------------------------------------------------------
async function fetchList() {
  loading.value = true
  try {
    const res = await getRoomTypes()
    // 后端直接返回数组；这个 || 兜底是为了兼容将来改成 { items } 的分页结构
    list.value = Array.isArray(res) ? res : (res?.items || [])
  } catch (e) {
    list.value = []
    handleApiError(e, '加载房型失败')
  } finally {
    loading.value = false
  }
}

// ---------------------------------------------------------------------------
// openCreate / openEdit — 打开弹窗
// ---------------------------------------------------------------------------
function openCreate() {
  isEdit.value = false
  form.value = { id: null, name: '', description: '' }
  showDialog.value = true
}

function openEdit(row) {
  isEdit.value = true
  form.value = { id: row.id, name: row.name, description: row.description || '' }
  showDialog.value = true
}

// ---------------------------------------------------------------------------
// save — 保存（新增或编辑共用）
// ---------------------------------------------------------------------------
async function save() {
  const valid = await formRef.value.validate().catch(() => false)
  if (!valid) return

  saving.value = true
  try {
    if (isEdit.value) {
      // 只提交可能变化的字段；description 为空时传 undefined（后端会忽略 null 字段）
      await updateRoomType(form.value.id, {
        name: form.value.name,
        description: form.value.description || undefined
      })
      ElMessage.success('已更新')
    } else {
      await createRoomType({
        name: form.value.name,
        description: form.value.description || undefined
      })
      ElMessage.success('已创建')
    }
    showDialog.value = false
    await fetchList()
  } catch (e) {
    handleApiError(e, isEdit.value ? '更新失败' : '创建失败')
  } finally {
    saving.value = false
  }
}

// ---------------------------------------------------------------------------
// toggleStatus — 启用 / 停用（只提交 isActive 一个字段）
// ---------------------------------------------------------------------------
async function toggleStatus(row) {
  const action = row.isActive ? '停用' : '启用'
  try {
    await ElMessageBox.confirm(`确定${action}「${row.name}」？`, '提示', { type: 'warning' })
  } catch {
    return  // 用户点了取消
  }

  try {
    await updateRoomType(row.id, { isActive: !row.isActive })
    ElMessage.success(`已${action}`)
    await fetchList()
  } catch (e) {
    handleApiError(e, `${action}失败`)
  }
}

// ---------------------------------------------------------------------------
// handleDelete — 删除
// ---------------------------------------------------------------------------
async function handleDelete(row) {
  try {
    await ElMessageBox.confirm(`确定删除「${row.name}」？删除后不可恢复。`, '提示', { type: 'warning' })
  } catch {
    return
  }

  try {
    await deleteRoomType(row.id)
    ElMessage.success('已删除')
    await fetchList()
  } catch (e) {
    handleApiError(e, '删除失败')
  }
}

onMounted(fetchList)
</script>
```

## 3.5 第 4 步：菜单为什么自动出现

不需要改 `MainLayout.vue`，也不需要改菜单配置。回顾 2.4 节：

这证明菜单确实是由 `meta.roles` 驱动的。**验证完记得改回来。**

## 3.6 第 5 步：按钮级权限

页面里已经用了三个**真实存在**的权限码（来自 `scripts/SeedBase.sql` 的菜单种子数据）：

| 按钮 | 权限码 |
|---|---|
| 新增房型 | `system:roomtypecreate` |
| 编辑 / 启用停用 | `system:roomtypeedit` |
| 删除 | `system:roomtypedelete` |

用 `admin` 登录时三个按钮都在（超管的 `permissions` 包含全部权限码）。

**自己验证一遍**（推荐做一次，理解最深）：

1. 用 admin 打开「系统设置 → 菜单权限配置」（原项目有此页）或直接查数据库 `RoleMenus`，
2. 把某个**非超管角色**（如 `Operator`）的 `system:roomtypeedit` 菜单取消授权，
3. 用该角色的账号登录 → 打开房型管理 → **编辑按钮消失**。

原理回顾（2.5 节）：`permissions` 来自 `/auth/me`，`v-permission` 在 `mounted` 时查不到就把元素从 DOM 删掉。

> 想加一个新权限码？两处都要动：① 数据库 `Menus` 表加一条带 `PermissionCode` 的记录；
> ② 前端按钮写 `v-permission="'你的码'"`。前端加权限一定是"后端先有码，前端才能用"。

## 3.8 扩展：接口是分页的怎么写

房型接口是"一次性返回数组"，真实项目里大多数列表是**分页**的。契约长这样
（后端 `PagedResult<T>`，`src/RBS.Core/Interfaces/Repositories/IRepository.cs`）：

```json
{ "items": [...], "total": 128, "page": 1, "pageSize": 20, "totalPages": 7 }
```

**三处改动**：

① `api/index.js` 加上 params：

```js
export function getTenants(params) {
  // params: { page, pageSize, keyword }
  return request({ url: '/tenants', method: 'get', params })
}
```

② 页面里增加分页状态 + `el-pagination`：

```vue
<el-pagination
  v-model:current-page="query.page"
  v-model:page-size="query.pageSize"
  :total="total"
  :page-sizes="[10, 20, 50]"
  layout="total, sizes, prev, pager, next, jumper"
  style="margin-top:16px;justify-content:flex-end"
  @current-change="fetchList"
  @size-change="onSizeChange"
/>
```

```js
const query = ref({ page: 1, pageSize: 20, keyword: '' })
const total = ref(0)

async function fetchList() {
  loading.value = true
  try {
    const res = await getTenants({
      page: query.value.page,
      pageSize: query.value.pageSize,
      keyword: query.value.keyword || undefined   // 空关键字不要传，避免后端拼 SQL 时多余条件
    })
    list.value = res.items || []
    total.value = res.total || 0
  } catch (e) {
    list.value = []; total.value = 0
    handleApiError(e, '加载失败')
  } finally {
    loading.value = false
  }
}

/** 改每页条数后回到第 1 页 */
function onSizeChange() {
  query.value.page = 1
  fetchList()
}

/** 点"查询"按钮时也要回第 1 页 */
function handleSearch() {
  query.value.page = 1
  fetchList()
}
```

③ 搜索框改为**提交式**（不再是 `computed` 本地过滤）：

```vue
<el-input v-model="query.keyword" placeholder="关键字" clearable @keyup.enter="handleSearch" />
<el-button type="primary" @click="handleSearch">查询</el-button>
<el-button @click="() => { query.keyword = ''; handleSearch() }">重置</el-button>
```

> **两个必须记住的细节**：
> 1. 后端分页参数名必须是 `page` / `pageSize`（不是 `current`/`size`，那是 Element 的命名）。
> 2. **查询条件变化、每页条数变化时都要把 `page` 重置为 1**，否则会出现"第 3 页查关键字，结果空列表"的经典 bug。

# 第 4 章 约定清单与常见问题

## 4.1 加功能必须遵守的约定

**加一个页面（列表 CRUD）—— 固定 5 步：**

1. `api/index.js` 追加接口函数（命名 `getXxx / createXxx / updateXxx / deleteXxx`）
2. 新建 `views/<模块>/index.vue`（照 2.6 节的骨架）
3. `router/index.js` 的对应 children 里加一条路由（`meta.title` / `icon` / `roles`）
4. 刷新页面，菜单**自动出现**
5. 需要按钮权限 → 后端加权限码，前端 `v-permission="'码'"`

**加一个二级菜单组：**

```js
{
  path: 'reports',                    // 父：无组件页面，只有分组
  component: RouteView,               // ★ 用 RouteView 当容器
  redirect: '/reports/daily',         // 点父菜单落到第一个子页
  meta: { title: '报表中心', icon: 'DataLine', roles: ['Admin'] },
  children: [
    { path: 'daily', name: 'ReportDaily', component: () => import('../views/report/daily.vue'),
      meta: { title: '收款日报', icon: 'Sunny' } }
  ]
}
```

**代码约定（照做能让你的代码和本项目其他 90 个页面长得一样）：**

| 约定 | 要求 |
|---|---|
| 组件写法 | 一律 `<script setup>`，不写 `export default` |
| 接口调用 | 组件里**只 import `api/index.js` 的函数**，不直接碰 axios、不写 URL 字符串 |
| 错误处理 | `catch (e) { handleApiError(e, 'xxx失败') }` |
| 写操作后 | 一律 `await fetchList()` 重新拉取，不手工改本地数组 |
| 表格 | 统一用 `.page-header` / `.search-bar` / `.table-actions` 全局类，不写局部样式重复造轮子 |
| 弹窗表单 | `ref="formRef"`，`save()` 第一句就是 `await formRef.value.validate().catch(() => false)` |
| 路径命名 | `path` 全小写无连字符；`name` 用 PascalCase |
| 状态生命周期 | 需要"重置为初始值"的对象用 `ref({...})` 整体替换，不要逐字段清空 |

## 4.2 常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| 登录成功但菜单空白 | `initFromRoutes` 在 `loadUserProfile` 之前调用，`roles` 还是空数组 | 确保 `await userStore.loadUserProfile()` 之后再 `initFromRoutes`（见 `MainLayout.vue`） |
| 刷新页面后用户信息/菜单都没了 | 页面刷新后 `user` 是空的，靠 `loadUserProfile()` 恢复 | 检查 `localStorage` 里 token 是否还在；检查 `/auth/me` 是否返回 `roles` |
| 按钮 `v-permission` 不生效（该隐藏的还在） | ① 权限码拼错；② 指令只在 `mounted` 执行一次，权限是之后才加载的 | 用 Vue DevTools 看 `useUserStore().permissions` 里有没有这个码；确认权限码和后端种子里的一致 |
| **刷新业务页后按钮全消失**（从别的页面点进来却正常） | 子组件 `onMounted` 早于父组件，页面在 `permissions` 为空时就挂载了，指令把按钮删了且不会重跑 | `MainLayout` 里写 `<router-view v-if="userStore.profileLoaded" />`（见第 16 步的详细说明） |
| 登录后布局一片空白（菜单和内容都没有） | 同上：`profileLoaded` 一直是 false（`/auth/me` 失败或没 await） | 看 Network 里 `/api/auth/me` 的状态码；确认 `MainLayout.onMounted` 里 await 了 `loadUserProfile()` |
| 请求全变 404 | Vite 代理目标端口不对 | 对准后端实际端口改 `vite.config.js` 的 `proxy['/api'].target` |
| 请求 401，一直跳登录 | token 过期（本项目 120 分钟） | 重新登录。刷新 token 的逻辑本项目没做 |
| 更新/删除"看起来失败"但数据其实变了 | 后端返回 204 没有响应体 | 判断成败看有没有抛异常，不要看返回值（见 3.1 的坑） |
| 子路由页面是空白 | 父路由 `component` 没写 `RouteView` | 二级菜单组的父路由必须 `component: RouteView` |
| 菜单图标不显示 | ① `meta.icon` 名字写错；② 忘了全局注册图标 | 名字要和 `@element-plus/icons-vue` 导出一致；确认 `main.js` 里的图标注册循环 |
| `v-permission` 报错 `getActivePinia` | Pinia 还没 `app.use` 就渲染了组件 | 检查 `main.js` 里 `app.use(createPinia())` 在 `app.mount()` 之前 |
| 直接访问子路径 404（开发环境） | 没开 history 回退 | `vite.config.js` 加 `historyApiFallback: true`；生产看 `nginx.conf` 的 `try_files` |
