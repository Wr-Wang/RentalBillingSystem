### 阶段一：P0 补表与补字段

**目标**：补齐所有缺失的数据库表和字段，消除运行时崩溃隐患。

| `PreviousContractId` | `UNIQUEIDENTIFIER NULL` | 上一份合同 ID，续签链追溯 |
| `OriginalContractId` | `UNIQUEIDENTIFIER NULL` | 原始合同 ID，全链路追溯 |
| `RenewalCount` | `INT NOT NULL DEFAULT 0` | 续签次数，合同编号 -R1/-R2 后缀 |

### 阶段三：P0 定时任务运行时引擎

**目标**：让已配置的 Job 能按计划执行，通知系统写路径完整闭口。

#### 3.1 调度引擎

| 步骤 | 内容 | 涉及文件 |
|------|------|---------|
| ① 引入 Cronos | NuGet 包 `Cronos` 用于 Cron 表达式解析 | `.csproj` |
| ② BackgroundService | `SchedulingHostedService` — 每 60 秒轮询 `JobScheduleExecutions`，匹配当前时间触发 Job | `src/RBS.Infrastructure/Scheduling/` 新增 |
| ③ 执行互斥 | 基于 `ScheduledTaskLogs` 表的互斥锁（`TaskName + CompanyId + TargetMonth` 唯一约束） | 新增 |
| ④ 超时检测 | 心跳 `HeartbeatAt` 超时 30 分钟标记为 Stale | 新增 |

#### 3.2 5 个 Job 实现

| Job | 触发条件 | 业务逻辑 | 通知目标 |
|-----|---------|---------|---------|
| `MonthlyFeeBillJob` | 每月约定日（如 25 日）08:00 | 按合同费用配置生成当月 `ReceivablePlans` | 通知运营人员 |
| `LateFeeCalcJob` | 每天 02:00 | `ReceivablePlans` 中逾期的按滞纳金规则计算 | 不通知 |
| `AutoRenewJob` | 每天 08:00（T-7 天） | 检查到期前 7 天且 `AutoRenew=true` 的合同 → 提交续签审批 | 通知系统管理员 |
| `CollectionJob` | 每天 09:00 | 逾期天数 → 催缴阶段 → 创建 `CollectionRecords` → 触发催缴动作 | 通知运营人员 |
| `RenewalReminderJob` | 每天 08:00（T-14 天） | 聚合到期前 14 天合同 → `NotificationService.NotifyRoleAsync("OpsSupervisor")` | 通知运营主管 |

#### 3.3 通知写路径闭口

| 触发源 | 通知内容 | 接收人 | 依赖 |
|-------|---------|:-----:|------|
| `RenewalReminderJob` | "本月 N 份合同即将到期" | OpsSupervisor + DeptManager | 3.2 Job 实现 |
| `CollectionJob` | "XX 合同逾期 N 天，已发送催缴" | 运营人员 | 3.2 + 催缴管理 |
| `MonthlyFeeBillJob` 完成 | "2026年8月应收已生成，共 N 条" | 财务人员 | 3.2 + 应收生成 |
| `AutoRenewJob` 完成 | "自动续签：成功 N 份，失败 N 份" | 系统管理员 | 3.2 + 续签管线 |
| Job 执行失败 | "XXXJob 执行失败：错误信息" | 系统管理员 | 3.1 异常捕获 |

## 依赖关系

```
阶段一（补表） → 阶段二（核心管线） → 阶段三（定时引擎）
                      ↑                       |
                      |                       ↓
                      └──── 阶段四（补充业务）──→ 阶段五（前端）
                                                 ↓
                                            阶段六（打磨）
```

- 阶段一必须最先完成（无表则所有写操作均崩溃）
- 阶段二和阶段三可并行部分任务（应收生成与定时引擎开发团队可分开）
- 阶段四依赖阶段二的催缴和会计部分
- 阶段五依赖阶段二的收款端点
- 阶段六可随时穿插
